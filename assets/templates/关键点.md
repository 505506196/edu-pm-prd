v2.8
【问题】：「一键复制全文」已经能带出原型图了，但 PM 反馈粘进文档后**图片发虚、质量不高**

【思路】：
1. **先量再改，别照直觉动手。** 直觉是"JPEG 0.85 压太狠"，实测把同一素材同一区域做四档对照——`JPEG .85` / `JPEG .95` / `PNG 无损` / `WebP .92`，**全部缩到 1200 后几乎看不出差别**，而不降采样的原图明显锐利。结论反过来了：**发虚是 `MAX_IMG_WIDTH = 1200` 那一步降采样丢的细节，不是 JPEG 压坏的**，换编码格式（哪怕换成无损 PNG）一点用都没有
2. **验收姿势本身是个坑。** 图在文档里的显示宽度被 §2.8 ④ 固化成表格「原型」列的宽度（实测 335px），**这个尺寸下 1200 和 2880 原图肉眼完全一样**——按默认大小看永远发现不了问题，差异只在读者放大看细节时暴露。所以 §5.2 加了一条：验收必须放大到 1000px 以上再看
3. **拐点靠体积曲线选，不拍脑袋。** 9 张真实素材实测：`1200/.85 = 0.90MB`、`1600/.9 = 1.65MB`、`2000/.9 = 2.20MB`、`2880 原尺寸/.9 = 3.60MB`。取 **2000 + 质量 0.9**——放大到 1500px 仍锐利，体积只有原尺寸的六成
4. **报体积要报剪贴板里的量。** 上面那些是解码后字节数，剪贴板里躺的是 base64 文本，**再膨胀 1.33×**。这份 PRD 实测：图片解码 2.83MB → 剪贴板 HTML **3.82MB**（改前 1.65MB）。按解码值向用户承诺会低估三分之一，粘不粘得进去看的是后者
5. WebP 更省（`2000/.9` 仅 1.34MB）且质量更好，但**钉钉/飞书/Word 对剪贴板内 base64 WebP 的支持没实测过**，核心场景不赌，留作已知选项写进规范
6. 联动更新：edu-pm-prd §2.8 ⑤（重写体积控制 + 三条踩坑）/ §2.8 取材限制（体积口径）/ §5.2（+1 条放大验收）/ 项目版 workflow 同步；真实 PRD 常量改 2000 + 0.9；回归 `file://` 39 + http 12 + 正文零丢失比对全绿

【问题】：HTML原型视觉效果一般，想接入 Pencil 设计工具画更精美的高保真原型

【思路】：
1. Pencil 作为可选增强，不作为必须依赖——没装Pencil也能跑通整个工作流
2. HTML原型完成后主动询问用户是否需要Pencil增强，让用户选择
3. 自动检测Pencil安装状态，未安装给安装引导，已安装检测MCP连接
4. 建立统一设计变量体系（$primary、$accent等），Pencil和HTML两端保持一致
5. 新增 HTML↔Pencil 视觉一致性校准步骤，避免PRD中左右截图不一致
6. 新增 MCP 连接故障排查方案（含WebSocket直连降级）
7. 更新到工作流 3.5 节
